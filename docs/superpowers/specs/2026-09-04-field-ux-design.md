## 적용 결정: 필요한 부분만 수정

사용자 요청에 따라 정부 가이드는 참고 근거이며 전체 준수나 수치 일괄 적용을 목표로 하지 않는다. 아래 화면별 제안도 전부 구현해야 하는 요구사항이 아니다.

- **우선 수정:** 잘못된 작업·언어·링크 표시, 초안·재녹음 손실, 잘못된 안전·성공 안내, 재생 범위 불일치 등 확인된 사용 실패와 오해 위험.
- **문제가 있는 곳만 수정:** 좁은 화면의 아이콘 압축·잘림, 흐린 초점, 읽기 어려운 줄바꿈, 핵심 행동을 가리는 반복 정보. 해당 화면과 컴포넌트만 바꾼다.
- **현재 유지:** 충분히 큰 본문과 터치 영역, 문제 없는 색상·배치·컴포넌트. 가이드와 다르다는 이유만으로 바꾸지 않는다.
- **검증 후 선택:** 제목 28px 통일, 버튼 56px 통일, 여백·굵기 전면 조정, 추가 공유 편의, 단계 위치 복원 등. 실제 과제 수행에 이득이 확인되거나 별도 승인된 경우만 채택한다.

우선순위는 안전·작업 정확성 → 입력 보존·복구 → 읽기·조작의 실제 장애 → 미관·편의다. 접근성 결함을 선택적 장식으로 취급하지 않되, 정부 수치와 다르다는 사실만으로 결함이라 판정하지 않는다.

## 1. 확인한 정부·공공 가이드와 적용 범위

2026-09-04 공식 웹 원문을 확인했다. 금융위 발표자료와 KRDS 웹 문서를 사용했으며, 금융위 첨부 PDF는 도구에서 열리지 않아 전체 구성지침 PDF를 읽었다고 주장하지 않는다. 금융위 공식 HTML에서 13개 원칙과 적용 대상은 확인했다.

| 자료 | 확인한 사실 | 밭머리 적용 |

이 계획은 밭머리에 정부 지침의 법적 의무가 있다고 판정한 문서가 아니다. 정부 인증이나 WCAG 인증을 주장하지 않는다. 은행의 금융사기 신고·이체 전용 구성, 공공기관 공식 배너·로고·정부 서체 일괄 교체는 적용하지 않는다.

고령자 전용 고정 글꼴 크기나 버튼 좌표를 위 원문에서 확인한 것은 아니다. 아래 20px·56px·간격값은 밭머리용 후보이며 정부 의무 수치가 아니다. CSS px를 기기의 물리적 mm 또는 native dp/pt와 동일시하지 않는다.

## 2. 대안과 선택

| 안 | 장점 | 비용·위험 | 결론 |
|---|---|---|---|
| A. 기존 화면 재배치와 상태 교정 | 기존 컴포넌트·브랜드·API 재사용, 작은 변경으로 검증 | 기존 녹음→확인→전달 구조 유지 | 추천 |
| B. 모든 것을 한 질문씩 안내 | 첫 사용자에게 집중하기 쉬움 | 전체 지시 검토·반복 사용이 느려짐 | 차단된 보완 질문에만 사용 |
| C. 음성 중심 단일 화면 | 읽기보다 듣기 선호 사용자에게 유리할 가능성 | 언어별 기기 음성 지원과 단계 음성 계약, 안전 검토 부담 | 별도 연구로 보류 |

기본 화면을 쉽게 만든다. 기능을 별도 ‘고령자 모드’ 안에 숨기지 않는다. 사용자의 나이·국적을 읽기 능력이나 스마트폰 숙련도로 취급하지 않는다.

핵심 원칙은 현재 행동 하나, 판단에 필요한 사실, 틀렸을 때 돌아오는 길이다. 보기 좋은 농업 장식보다 정확한 전달과 회복을 먼저 개선한다.

## 3. 디자인 기준 후보

모든 값은 일반 브라우저 기본 글자 크기 16px에서 환산한 검증 후보이지 일괄 변경 명세가 아니다. 현재 값으로 읽기·조작 문제가 없으면 유지한다. 해당 요소에 문제가 확인되었을 때만 아래 후보를 비교한다. root 글자 크기는 100%를 유지하고 수정하는 앱 요소에서는 rem을 사용한다. 랜딩 전체 스타일은 이번 작업 대상이 아니다.

| 요소 | 후보값 | 검증 조건 |
|---|---|---|
| 본문 | 1.25rem = 20px, 400 또는 500 굵기 | 현재 큰 글자 유지. 모든 문장을 800·900으로 표시하지 않음 |
| 보조 설명·필드명 | 1.125rem = 18px 이상 | 경고·수량·핵심 안내를 작은 글씨로 숨기지 않음 |
| 화면 제목 | 1.75rem = 28px, 700 | 언어별 문구를 먼저 줄이고 글자 자동 축소 금지. 필요 시 자연 줄바꿈 |
| 일반 핵심 수량 | 1.5rem = 24px, 700 | 숫자와 단위 함께 유지 |
| 수량 변경 비교 | 1.875rem = 30px, 700 | 20망 → 15망이 좁은 화면에서도 잘리지 않음 |
| 행간 | 기본 1.5, 긴 설명·네팔어 1.6~1.7 후보 | 모음 부호·상하단 글리프 충돌 없음. 실제 폰트로 확인 |
| 주요 버튼 | 최소 높이 3.5rem = 56px | 고정 높이가 아님. 글자 확대·번역 줄바꿈 때 성장 |
| 보조 버튼 | 최소 높이 3rem = 48px | 필수 터치 영역은 44×44 CSS px 미만으로 줄이지 않음 |
| 이전·다음 | 현재 52px 이상 영역 유지, 아이콘 24px 축소 금지 | 가운데 음성 버튼과 같은 좁은 행에 억지로 끼우지 않음 |
| 버튼 간격 | 기본 12px, 혼동 위험 동작 사이 16px | 재발급·취소·확정을 붙이지 않음 |
| 모바일 여백 | 바깥 16px, 카드 안 16~20px | 큰 글자를 유지하면서 장식 여백을 줄임 |
| 정보 그룹 | 내부 8~12px, 그룹 사이 20~24px | 필요한 묶음만 구별하고 카드 중첩 축소 |
| 초점 표시 | 단색 3px outline, offset 2px 후보 | 인접 배경과 3:1 이상을 목표로 측정 |
| 텍스트 대비 | 일반 안내 4.5:1 이상, 핵심 수량·위험 안내 7:1 목표 | 7:1은 밭머리 강화 목표이며 모든 정부 요구라고 말하지 않음 |

주요 색 조합은 기존 리뷰에서 양호했다. 전체 색상·브랜드 교체보다 흐린 focus ring과 상태 의미를 먼저 수정한다. 녹색 체크는 실제 성공에만 사용하고 영상 없음·확인 불가에 사용하지 않는다.

KRDS 권장 터치 44×44와 WCAG 2.2 AA 최소 타깃 24 CSS px를 혼동하지 않는다. 고령 현장 사용에서는 최소 준수보다 현재 큰 조작 영역 유지가 중요하다.

## 4. 공통 레이아웃·동작

1. 현재 화면 목적과 작업을 먼저 표시한다.
2. 결정에 필요한 사실·질문·안전 경고를 표시한다.
3. 주 행동 하나와 낮은 강조의 취소·이전 행동을 제공한다.
4. 번역 근거·기술 상세는 필요한 경우 펼쳐서 확인한다.
5. 위험·미확정은 상세 안에 숨기지 않는다.

언어·화면·변경 상태를 장식 배지로 반복하지 않는다. 작업 중 홍보 홈으로 보내는 링크를 줄이고, 작업 목록 복귀를 명확히 한다. 키보드 초점과 화면 제목은 전환 때 이동하지만 재생·polling마다 사용자 위치를 뺏지 않는다. 네팔어와 베트남어는 실제 글리프와 문장으로 검증하며 임의 음수 자간이나 강제 anywhere 줄바꿈을 사용하지 않는다.

붙임 CTA는 내용·키보드·경고를 가리지 않는 경우에만 적용한다. 320px와 200% 확대에서 공간이 부족하면 문서 흐름에 배치한다. 고정 하단 내비게이션과 주 행동을 이중으로 쌓지 않는다.

50초 시점에 녹음 종료 예고를 표시하는 방안을 검증하되 기존 60초 녹음·요청 timeout 및 보안 만료 계약을 임의로 늘리지 않는다. 충분한 시간 원칙은 검토를 자동 넘기지 않고, 중단 후 복구를 제공하는 것으로 먼저 반영한다.

## 5. 화면별 디자인

### 농장주 로그인·홈·목록

로그인 순서: 화면 목적 → 농장 코드 → PIN → 접속 → 운영자 발급 안내. 실제 문의 채널이 등록되지 않았다면 전화번호나 채널을 만들어 쓰지 않는다. 오류 뒤 입력과 초점을 불필요하게 지우지 않는다.

홈에는 새 작업 말하기를 주 행동으로 두고, 오늘 작업팀과 기존 작업 목록을 제공한다. 목록은 작업명·장소·수량·제공된 완료 시간으로 구분한다. 여러 작업을 다시 찾고 기존 상세/수량 변경으로 들어갈 수 있어야 한다. 읽기 전용 legacy 표시는 유지한다.

게시·팀 배정·링크 발급은 서로 다르다. 확인하지 않은 읽음·이해·완료 상태를 만들지 않는다.

### 농장주 녹음

오늘 할 일 안내 → 어디서·무엇을·얼마나·언제까지 → 큰 녹음 버튼 → 녹음 시간·음량 → 녹음 후 원음 듣기와 내용 확인.

정지 아이콘만 두지 않고 ‘녹음 끝내기’ 문구를 사용한다. 새 녹음이 실제 시작된 후 기존 음성을 교체한다. 권한·장치·사용 중 오류를 구분하고, 원음 재생 실패도 설명한다. raw audio는 현재 브라우저 메모리에만 잠시 있고 서버나 영구 저장소에 남기지 않는다.

### 농장주 검토·보완

제목: 작업 내용이 맞나요?

순서:

- 장소·수량·완료 시간의 간결한 사실 묶음.

- 실행 단계 제목과 설명.

- 전달 메모가 있으면 표시.

- 안전·미확정·차단 사유.

- 확정 또는 허용된 owner override.

- 원문·번역 근거의 상세.

필수 실행 내용을 숨기거나 읽었다는 체크박스로 책임을 넘기지 않는다. 수량·장소·시간 옆의 ‘다시 말하기’는 기존 audio supplement를 재사용한다. 한 항목을 고치더라도 서버가 돌려준 전체 결과를 다시 확인한다. 지정 필드만 바뀐다고 현재 계약 이상으로 약속하지 않는다.

UNKNOWN은 부족한 정보의 질문을 보여주고, HIGH·지원 제외 작업은 전달할 수 없다고 설명한다. 안전수칙을 더 말하면 HIGH가 통과할 것처럼 안내하지 않는다. deadline·notes가 비어 있다는 이유로 새로운 필수 질문을 강제하지 않는다.

복구: 같은 인증 농장의 해석된 초안만 복원. 원음은 복원되지 않을 수 있음을 안내한다. API가 구현·검증되기 전 자동 저장을 보장하는 문구를 배포하지 않는다.

### 농장주 전달·작업팀

확정 완료와 작업·장소·수량을 먼저 보여주고 전달 방식을 선택한다.

- 내 폰으로 함께 보기.

- 작업팀에 배정하기.

- 링크로 보내기.

세 방식의 세부 옵션을 동시에 모두 펼치지 않는다. 언어 선택은 농장주에게 ‘베트남어 · Tiếng Việt’, ‘네팔어 · नेपाली’로 표시한다.

발급 카드의 실제 언어와 선택 중인 언어는 분리한다. 선택 변경만으로 기존 링크 라벨이 바뀌지 않는다. 기본 공유 기능을 사용할 수 있으면 제공하고, 복사를 대안으로 남긴다. 재발급은 같은 작업·같은 언어의 기존 링크가 중단됨을 사전 설명한다. 다른 언어 링크까지 모두 폐기된다고 잘못 설명하지 않는다.

팀 화면은 QR와 명단을 구분한다. 참가자 행에 별명·언어·배정 작업을 표시하고, 선택한 작업의 장소·수량을 확인한 뒤 배정한다. QR·원격 링크는 응답 expires_at을 표시한다. 근거 없이 ‘오늘 자정까지’나 다른 만료 시간을 고정 문구로 쓰지 않는다. 배정 취소 API가 없으므로 취소 완료 기능을 약속하지 않는다.

### 농장주 수량 변경

대상 작업·장소 → 현재 수량 → 새 수량 녹음 → 이전/새 수량 비교 → ‘15망으로 변경’ → 성공 안내.

현재 작업을 벗어나면 preview를 재사용하지 않는다. version conflict 시 최신 내용 재확인이 먼저다. 성공은 ‘20망에서 15망으로 변경했습니다’이며 ‘모두 확인했습니다’가 아니다.

### 근로자 진입·참가·대기

홈페이지의 근로자 진입과 /worker에서 QR 입력 전에 언어를 고를 수 있게 한다. 직접 팀 QR은 참여 폼 위에 언어 선택을 둔다. 선택 전 안내는 짧은 vi/ne 병기다.

정상 원격 링크의 작업 언어는 발급된 package.language_code가 권위다. 오류 안내 언어 선택을 작업 내용 번역 전환처럼 표현하지 않는다. 다른 언어 지시가 필요하면 농장주에게 해당 언어 링크를 요청한다.

별명 한 입력과 언어 선택만 유지한다. 참가 후 authenticated assignments 200 빈 배열이면 참가 상태와 배정 대기를 설명한다. 새 identity API나 worker briefing identity를 추가하지 않는다. 같은 브라우저에서 방금 받은 참가 이름은 메모리 표시 가능하지만 새로고침 후 검증되지 않은 이름을 로그인 사실처럼 쓰지 않는다.

### 근로자 작업 요약

작업명 → 장소·수량 → 전체 작업 듣기 → 완료 시간·메모·안전 → 단계별로 보기 → 단계 목록·출처.

동일 제목·최신/오늘 배지를 반복하지 않는다. 여러 작업이 있으면 작업·장소·수량으로 선택하고, 화면·음성·단계가 같은 session_id를 가리키게 한다. 최신 조회 실패 때 기존 내용을 최신이라고 단정하지 않고 마지막으로 받은 안내임을 밝힌다.

### 근로자 단계

작업명, 장소·수량·완료 시간, 현재 단계 번호를 compact하게 유지한다. 영상/대체 안내, 실행 설명, 안전 안내, 출처를 순서대로 표시한다.

듣기는 전체 폭으로 배치하고 현재 계약상 ‘전체 작업 듣기’로 표시한다. 이전/다음은 별도 행에 문구와 함께 제공한다. 미디어 재생은 명시적 사용자 행동에서만 시작한다.

현재 버전의 전체 안전 문구 다음 전체 단계 title·description을 서버 음성과 browser fallback 모두 같은 순서로 재생한다. pause/resume의 기기별 불안정성을 새 기능으로 떠안지 않고 우선 확실한 ‘정지’와 ‘다시 듣기’를 제공한다. 단계별 음성은 별도 계약 승인 전 보류한다. 장소·수량을 음성에 추가하는 것도 기존 TTS 계약과 hash를 변경하므로 이번 최소안에서는 화면의 핵심 정보로 보완하고 별도 필요성을 실사용에서 검증한다.

단계 복원은 같은 session·version에서만 한다. 새 version은 이전 음성·영상을 정지하고 첫 단계부터 재확인한다. 이전 버전을 실제로 봤을 때만 전후 수량을 비교한다. 처음 접속한 사용자에게 과거 수량을 추측해 보여주지 않는다.

마지막 버튼은 작업 목록으로 돌아간다. 실제 작업 완료를 기록하는 것으로 가장하지 않는다.

### 오류·안전 출처

오류는 상태 → 현재 볼 수 있는 것 → 다음 행동 → 안내 언어 선택으로 통일한다.

- 네트워크·서버: 재시도.

- 만료: 농장주에게 새 링크/QR 요청.

- 접근 불가: 사유를 일반화.

- 영상·음성 실패: 중립 안내와 텍스트 대안.

- 미확정: 해당 필드가 안내되지 않았다고 표시. null을 해당 없음으로 추론하지 않음.

안전 문구 옆에는 검증 출처 보기. 이미 제공된 source_detail만 소비하며 원문 미검수 자료를 공식으로 쓰지 않는다. 정부 UI/UX 가이드를 읽은 것과 농작업 안전 가이드의 source verification은 전혀 다른 검증이다.

## 6. 구현 전 문서 게이트

- 초안 복구 GET은 신규 API이므로 PRODUCT_SPEC, ARCHITECTURE, openapi, FAILURE_MODES, BACKLOG와 필요한 DATA_MODEL 설명을 먼저 갱신한다.

- DATA_MODEL tts_assets의 step 중심 설명과 PRODUCT_SPEC/AI_CONTRACTS의 전체 package 설명이 어긋나는 부분이 있다. 상위 계약을 확인해 문구를 동기화한 후 media 작업을 진행한다. 계획 문서만으로 임의의 새 오디오 계약을 만들지 않는다.

- 나머지 오류 교정은 기존 계약 불변인지 먼저 확인하고, 동작 변경이면 관련 문서를 같은 작업에서 갱신한다.

- 계획 승인 전 위 권위 문서와 제품 코드를 수정하지 않는다.

## 7. 검증과 완료 기준

개발 검증:

- 320/360/390/768px와 desktop; ko/vi/ne.

- 실제 브라우저 200% 확대 및 시스템 큰 글씨. 잘림·겹침·행동 은폐 없음.

- 키보드·스크린리더·강제 색상·reduced motion. 명확한 초점과 처리 알림.

- 잘못된 작업·언어·버전의 화면/오디오 결합 0건.

- 같은 농장 초안 복구, 타농장 차단, 명시적 logout/farm 전환 초기화.

- 기존 안전·인증·version·원음 삭제 gate 유지.

- mock은 구조 검증용. 실제 미디어·기기 음성·원어민 이해를 대신하지 않음.

실사용 탐색:

- 농장주 5, vi 5, ne 5 제안. 표본은 통계적 대표성을 보장하지 않음.

- 본인 기기, 실제 숙련도 차이, 안전한 밝음·소음·약한망 환경.

- ‘어디에서 무엇을 얼마나 언제까지’를 자기 말로 설명.

- 잘못된 작업·언어·수량 전달·안전 오해 0건을 출시 판단의 필수 후보로 둠.

- 일반 과제 각 집단 4/5 독립 완료는 초기 탐색 목표이지 정부 기준이 아님.

- 녹화는 별도 동의, 결과와 무관한 보상, 근로자는 감독자 눈치 없이 개별 확인.
