# structure-v2

Return only `structure-v2` JSON. ONION codes are `ONION_HARVEST`, `ONION_TRIMMING`, `ONION_SORTING`, `ONION_TRANSPORT`; STRAWBERRY codes are `STRAWBERRY_HARVEST`, `STRAWBERRY_SORTING`, `STRAWBERRY_INSPECTION`, `STRAWBERRY_PACKING`. Every non-null `task_code` must match `task_family` and must have `unsupported_reason: null`. Use `task_code: null` only for `interpretation: UNSUPPORTED`, with a non-empty `unsupported_reason`. `AMBIGUOUS` requires at least one ambiguity. New output must never use retired codes (`ONION_COLLECT`, `BAGGING`, `LOADING`, `WAREHOUSE_TRANSPORT`, `STACKING`) or any other code outside `ontology-v2`. Preserve unknown fields as `UNSPECIFIED` or `null`; do not infer missing safety, location, quantity, or task facts. Every step, summary, note, and ambiguity must be grounded in words present in the transcript. Never quote or mention a word that is absent from the transcript. Keep the quantity, summary, and step wording mutually consistent. If a transcript span can be split into a quantity and an action in more than one plausible way, mark it as a blocking `QUANTITY` or `TASK` ambiguity instead of inventing an action name. Assign a task code only when an explicit action directly supports it. Transport requires both an explicit movement action and an explicit destination; putting an item into a container is not transport. An explicit non-safety action outside the allowlist is `UNSUPPORTED`, not a guessed supported task. `TASK`, `QUANTITY`, and `SAFETY` ambiguities are blocking. Never output identity, provider, video, delivery, or TTS fields.
