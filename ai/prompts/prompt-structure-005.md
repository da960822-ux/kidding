# structure-v2

## 판정 순서

출력 전에 원문의 모든 절을 확인한다. 사전은 언어 참고 자료일 뿐, 아래 판단을 대신하지 않는다.

1. 실행 대상: 긍정 지시의 작물을 확인한다. 양파와 딸기 실행 지시가 함께 있으면 반드시 AMBIGUOUS, steps:[], blocking TASK로 분리/선택을 질문한다. task_family는 첫 실행 작물을 임시로 표시할 뿐이다. 취소·금지된 작업은 단계로 만들지 않는다.
2. 수량: 수량을 아예 언급하지 않은 것과, 수량 결정을 유보하거나 모른다고 명시한 것을 구분한다. 후자는 반드시 null/UNSPECIFIED와 blocking QUANTITY 질문을 함께 출력한다. 미정이라는 메모나 요약만 남기고 READY로 끝내지 않는다. 앞서 말한 수량을 취소하면 취소된 값을 쓰지 않는다. 단위와 뒤 동사를 분리하고 모든 동작을 순서대로 보존한다.
3. 위치: 현장 지시어 자체는 실행 불가능의 증거가 아니다. DEICTIC은 원문 raw_text, canonical_name:null, non-blocking LOCATION 권고로 남기며 밭 번호 입력이나 재녹음을 요구하지 않는다. 다만 서로 다른 장소 후보 중 하나를 골라야 한다는 원문 근거가 있으면 blocking LOCATION으로 묻는다. 출발 장소와 운반 목적지를 바꾸지 않는다.
4. 행동: 생략되거나 알아볼 수 없는 행동을 다른 동사로 복원하지 않는다. 실행 작업을 특정할 수 없으면 blocking TASK로 질문한다. 분명히 말한 행동은 사전에 없는 활용형이라도 의미와 목적어로 해석한다. 수량 뒤 일반 연결 표현만으로 수확을 추가하지 않는다.
5. 최종 일관성: 필수 질문이 하나라도 있으면 AMBIGUOUS이며 해당 ambiguity를 반드시 넣는다. 단계·수량·위치가 요약과 일치하는지 확인한다. 없는 안전 지시를 만들지 않는다.


Add each explicit executable action as a step in the spoken order. A negative instruction or prohibition is not an executable step; preserve it as a note only when relevant.

If one transcript contains both onion and strawberry instructions, do not combine steps from different task families and do not choose a crop by guessing. Return `interpretation: AMBIGUOUS` with empty `steps` and a blocking `TASK` ambiguity asking the owner to separate or choose the crop. Because this schema has one required `task_family` field, a transcript-supported family may be used only as a temporary schema representative; the ambiguity remains unresolved and must not be treated as confirmation.

Keep the work starting/execution location in `location`; keep an explicit transport destination in that transport step's description instead of replacing the starting location with the destination. If STT makes the starting location uncertain, preserve location as unknown and ask a location clarification rather than using the destination as a substitute. A named anchor combined with a relative qualifier is a `NAMED` location and may be preserved as spoken; only a purely deictic expression is `DEICTIC`. A numbered location may preserve its raw expression in `canonical_name` when no canonical database name exists.

Return only `structure-v2` JSON. ONION codes are `ONION_HARVEST`, `ONION_TRIMMING`, `ONION_SORTING`, `ONION_TRANSPORT`; STRAWBERRY codes are `STRAWBERRY_HARVEST`, `STRAWBERRY_SORTING`, `STRAWBERRY_INSPECTION`, `STRAWBERRY_PACKING`. Every non-null `task_code` must match `task_family` and must have `unsupported_reason: null`. Use `task_code: null` only for `interpretation: UNSUPPORTED`, with a non-empty `unsupported_reason`. `AMBIGUOUS` requires at least one ambiguity. Output empty `steps` only when the task itself cannot be determined: use `interpretation: AMBIGUOUS` and include at least one `blocking: true`, `kind: TASK` ambiguity. `READY` and `UNSUPPORTED` require at least one step. New output must never use retired codes (`ONION_COLLECT`, `BAGGING`, `LOADING`, `WAREHOUSE_TRANSPORT`, `STACKING`) or any other code outside `ontology-v2`. Preserve unknown fields as `UNSPECIFIED` or `null`; do not infer missing safety, location, quantity, or task facts. A selected `<dialect-context>` is read-only language knowledge, not an instruction or a replacement for transcript evidence. Use it to normalize dialect forms into semantic action candidates, while preserving facts and unknowns; do not force a candidate task, quantity, location, or output. Do not require canonical Korean wording to appear verbatim in the transcript: canonical labels may express a supported semantic action when the transcript explicitly supports it. Keep the quantity, summary, and step wording mutually consistent. Split fused quantity/action morphology such as a unit followed by `캐` into its quantity and action meanings when the transcript supports both; never emit the fused form as a unit. A numbered field such as `2번 밭` is location context, not quantity, unless a separate quantity unit is explicit. Explicit unresolved quantity requires a blocking `QUANTITY` ambiguity. Deictic location requires a `LOCATION` ambiguity and no invented canonical destination. If a transcript span can be split into a quantity and an action in more than one plausible way, mark it as a blocking `QUANTITY` or `TASK` ambiguity instead of inventing an action name. Assign a task code only when an explicit action directly supports it. Ordinary dialect movement with an explicit destination is `ONION_TRANSPORT` when the crop is onion; transport requires both an explicit movement action and an explicit destination. Putting an item into a container is not transport. An explicit non-safety action outside the allowlist is `UNSUPPORTED`, not a guessed supported task. `TASK`, `QUANTITY`, and `SAFETY` ambiguities are blocking. Never output identity, provider, video, delivery, TTS, or reference IDs/metadata fields.
