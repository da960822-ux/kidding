# 세 지시의 지시보드·근로자 출력 검증

2026-09-04. 작업 구조는 대체로 보존되지만, 금지문 전달과 수량 단위 번역에는 문제가 있다. 특히 ③은 게시 검증을 통과하면서도 “던지지 말 것”이 전체 음성과 단계 상세 화면에서 빠진다.

## 검증 범위

- 사용자가 제공한 정확한 텍스트 3건을 현재 AI 런타임에 각각 3회 입력했다. 구조화 9회 모두 실제 provider 호출이다.
- 현재 작업 트리의 Node 구조화·번역·TTS와 BE schema·위험·확정 검증을 사용했다. HEAD는 `ff68b9595fbaae6849ed3df0108a4e49947f8b49`이며, 기존 미커밋 변경도 포함한다. 실행 전후 대상 소스 hash는 동일했다.
- 현재 DB의 영상과 가이드 데이터만 읽었다. DB에서 읽은 `verified` 값은 이번 작업에서 PDF 원문을 새로 대조했다는 뜻이 아니다. 이번 단계 설명은 모두 가이드 MISS에 따른 `AI_TRANSLATION`이었다.
- ①·③의 첫 결과로 베트남어·네팔어 패키지 4개와 실제 TTS MP3 4개를 생성했다. BE 패키지 검증과 음성 입력 문자열 일치 검증을 통과했다. 이것은 번역 의미 품질의 합격을 뜻하지 않는다.
- 생성 결과를 읽기 API 응답으로 주입하여 현재 React 화면을 Chromium 430×932에서 확인했다. 농장주 화면 3개와 근로자 언어별 화면 4개를 확인했고 브라우저 예외는 없었다. 브라우저 대체 음성은 발화 문자열을 캡처했으며 실제 기기 발음 평가는 하지 않았다.
- 입력 음성이 없으므로 STT는 검증하지 않았다. DB 저장·게시·실제 근로자 전송·원어민 검수는 수행하지 않았다. MP3는 DB 음성 저장 전 결과이며 패키지의 `audio_url:null`은 이 검증 방식에 따른다.
- 제품 코드와 계약 문서는 수정하지 않았다. 이 디렉터리의 재현 스크립트·결과·캡처만 추가했다.

## ① 순서 + 수량

> 아랫밭 양파 20망 캐서 상한 건 빼고 창고로 옮겨.

3회 모두 수량 `20망`, 출발지 `아랫밭`, 수확·선별·운반의 순서, 운반 목적지 `창고`를 보존했다. 목적지는 별도 요약 필드가 아니라 운반 단계 설명에 들어간다.

첫 실행의 농장주 확인 화면:

1. **양파 수확:** 아랫밭에서 양파 20망을 캡니다.
2. **양파 선별:** 상한 양파를 제외합니다.
3. **양파 운반:** 선별한 양파를 창고로 옮깁니다.

두 번째 실행만 아랫밭을 `DEICTIC`으로 분류하여 non-blocking 위치 확인을 요구했다. 원문은 유지했고, 농장주가 현장 위치 안내를 선택하는 기존 전달 경로를 사용할 수 있다. 나머지 2회는 `READY`였다.

베트남어 실제 단계 설명:

1. `Ở ruộng phía dưới, tôi thu hoạch 20 bao hành tây.`
2. `Loại bỏ hành tây bị hỏng.`
3. `Chuyển những củ hành tây đã được chọn lọc vào kho.`

수확·선별에는 승인된 사전 생성 영상이 연결되고, 운반에는 영상 없이 글과 음성이 연결됐다. 영상은 해당 작업 코드의 일반 안내이며 이 지시 문장으로 새로 생성한 영상이 아니다.

**발견:** 베트남어 수량 카드에는 `20 mạng`, 수확 설명에는 `20 bao`가 표시됐다. 수량 숫자는 유지되지만 단위 번역이 일치하지 않는다. 네팔어 수량 카드는 `20 जाल`이었다. 단위 표현의 현장 적합성은 원어민 확인이 필요하다.

## ② 부정문

> 양파를 던지지 말고 상한 것은 절대 정상 양파랑 섞지 마.

3회 모두 다음 메모를 보존했다.

> 양파를 던지지 말 것. 상한 양파를 정상 양파와 섞지 말 것.

그러나 금지문을 실행 작업으로 만들지 않는 현재 규칙에 따라 `steps:[]`, `AMBIGUOUS`, blocking `TASK`가 반환됐다. 농장주 화면에 “실행 단계 없음”, “지금은 전달할 수 없습니다”와 작업 보완 요청이 표시된다. `CONFIRM`과 `PUBLISH_AS_IS` 모두 `OVERRIDE_NOT_ALLOWED`였다.

**이 문장만으로는 근로자 보드·번역·TTS가 생성되지 않는다.** 수확·선별·운반 등 실행할 작업을 보완해야 한다. 두 금지문의 한국어 보존은 확인했지만, ②의 베트남어·네팔어 번역 품질을 검증했다고 볼 수는 없다.

## ③ 긴 복합지시

> 오전까지 아랫밭 양파 20망을 캐고, 상했거나 물러진 건 따로 빼. 다 끝나면 던지지 말고 상자에 담아서 창고로 옮겨.

3회 모두 `READY`, `20망`, `아랫밭`, `오전까지`, 수확·선별·운반의 순서를 보존했다. 상자에 담는 행동은 별도 포장 카드가 아닌 운반 단계 설명에 포함됐다. 금지문은 세 번 모두 메모에만 들어갔다.

첫 실행의 농장주 확인 화면:

1. **양파 수확:** 아랫밭에서 양파 20망을 캡니다.
2. **손상 양파 분리:** 상했거나 물러진 양파를 따로 뺍니다.
3. **양파 운반:** 작업을 마친 뒤 양파를 상자에 담아 창고로 옮깁니다.

완료 시간은 `오전까지`, 메모는 `양파를 던지지 말 것.`이다.

| 항목 | 베트남어 실제 출력 | 네팔어 실제 출력 |
|---|---|---|
| 장소 | Cánh đồng phía dưới | तल्लो खेत |
| 수량 카드 | 20 lưới | 20 जाल |
| 완료 시간 | đến buổi sáng | बिहानसम्म |
| 금지문 메모 | Không được ném hành tây. | प्याज नफ्याँक्नुहोस्। |
| 운반 설명 | Sau khi hoàn thành công việc, cho hành vào thùng rồi chuyển vào kho. | काम सकेपछि प्याजलाई बाकसमा राखेर गोदाममा सारिन्छ। |

금지문 번역의 부정은 남아 있다. 하지만 전달 경로에서 누락된다.

| 확인 지점 | 베트남어 | 네팔어 |
|---|---|---|
| 첫 화면에 금지문 표시 | 없음 | 없음 |
| 접힌 단계·음성 안내를 펼친 뒤 메모 표시 | 있음 | 있음 |
| 단계 상세 화면에 금지문 표시 | 없음 | 없음 |
| 서버 전체 TTS 입력에 금지문 포함 | 없음 | 없음 |
| 브라우저 대체 전체 음성에 금지문 포함 | 없음 | 없음 |
| 서버 전체 TTS 입력에 오전 마감 포함 | 없음 | 없음 |

현재 첫 화면은 첫 단계 제목, 장소·수량·완료 시간, 첫 단계 시작 버튼을 먼저 보여준다. 작업 목록과 메모·전체 듣기는 접힌 영역에 있다. 근로자가 바로 첫 단계를 시작하면 금지문을 보지 못한 채 단계 화면으로 이동한다.

베트남어 전체 TTS에 실제로 들어간 문자열:

```text
Thu hoạch hành tây Ở ruộng phía dưới, tôi thu hoạch 20 bao hành tây.
Phân loại hành tây bị hư hỏng Loại riêng những củ hành bị hỏng hoặc bị mềm nhũn.
Vận chuyển hành tây Sau khi hoàn thành công việc, cho hành vào thùng rồi chuyển vào kho.
```

위 입력에는 `Không được ném hành tây.`와 `đến buổi sáng`가 없다. 또한 수량 카드의 `lưới`와 수확 설명의 `bao`도 다르다. 마감 번역이 원문의 “오전까지”를 정확히 전달하는지는 별도의 원어민 검수가 필요하다.

## 원인과 조치 우선순위

1. **금지문과 마감의 전체 음성 누락 — AI 주담당.** `ai/lib/worker-briefing-v2.mjs:84`는 `safety`와 단계 제목·설명만 합친다. `notes`와 `deadline`은 포함하지 않는다. `backend/app/main.py:1393`의 기대 음성 문자열도 같은 구성이므로 검증을 통과한다. `src/webapp/WorkerScreens.tsx:23`의 브라우저 대체 전체 음성도 같은 누락이 있다. “전체 지시”에 반드시 포함할 필드를 계약에서 먼저 정리하고 생성·검증·대체 재생을 함께 맞춰야 한다.
2. **금지문이 접힌 메모에만 표시 — FE 주담당.** `src/webapp/WorkerScreens.tsx:124`의 메모는 닫힌 `details` 안에 있다. 같은 파일의 단계 상세 화면은 메모를 렌더링하지 않는다. 금지 사항을 작업 시작 전과 관련 단계에서 확인할 수 있어야 한다.
3. **수량 단위 문맥·일관성 부족 — AI 주담당.** `ai/lib/worker-briefing-v2.mjs:45`는 `망`만 번역에 넘기며 provider는 작물·수량 문맥 없이 `Translate into ...`로 번역한다. 설명 번역은 별도 호출이다. 계약의 수량 템플릿 요구와 현재 구현의 차이를 정리하고 현장 단위를 일관되게 사용해야 한다.

부정문을 무조건 `safety[]`로 옮기는 방식은 현재 안전 판정과 검수 출처 gate에 영향을 준다. 이번 확인에서는 그런 변경이나 게시 차단 우회를 하지 않았다. 금지문의 보존·표시·낭독을 함께 검증하는 수정이 필요하다.

## 전달 방식과 이번 검증의 구분

정상 서비스에서는 농장주 확인 후 같은 버전의 두 언어 패키지를 저장하고, 현장에서 함께 보기·언어별 24시간 링크·오늘 작업팀 QR 및 개인 배정에서 해당 패키지를 사용한다. 근로자의 지시 확인 버튼은 작업 완료 보고가 아니다.

이번 검증은 게시 직전 생성 패키지와 실제 화면 렌더링을 확인한 것이다. 근로자에게 링크를 발급하거나 메시지를 보내지는 않았다.

재현: `backend/.venv/Scripts/python.exe evals/results/instruction-board-20260904/check.py`는 실제 provider 비용이 발생하며 결과를 재생성한다. 화면 재현은 mock API를 끈 Vite를 4187 포트에서 실행한 뒤 `node evals/results/instruction-board-20260904/check-render.mjs`를 사용한다. 전체 관찰값은 [browser-checks.json](browser-checks.json), 실행 환경과 소스 hash는 [metadata.json](metadata.json)에 있다.
